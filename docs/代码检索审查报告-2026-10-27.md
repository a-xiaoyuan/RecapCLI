## 已实现能力及依据

| 能力 | 仓库证据与当前边界 |
| --- | --- |
| 文件名检索 | `revocli/tools/filesystem.py` 的 `find_files` 支持名称或相对路径子串、glob，默认忽略大小写；返回路径、截断状态和可能的预算原因。 |
| 文本检索 | `search_text` 按行做字符串包含匹配，可指定起点、大小写及结果上限；返回路径、行号、引用、行文本和扫描统计。默认 50 条，最多 200 条，行文本最多 300 字符；扫描有条目、文件、字节和时间预算。大于 1 MiB 的文件及检测到的二进制文件会跳过。 |
| 工作区读取和浏览 | `read_file` 支持按行读取和引用；`list_directory` 返回受限目录树。路径检查限制在工作区内，遍历跳过若干内部目录及链接。 |
| 工具接入 | `revocli/tools/registry.py` 提供模型工具定义、参数校验和分发；`core/agent.py` 提示模型使用上述读取、搜索工具。默认只读，写入与执行需分别开启。 |
| 其他能力 | README 和代码包含 ReAct / 计划执行、会话存储、历史压缩、长期记忆、任务追溯、编辑备份恢复及命令执行。命令执行不是系统沙箱。 |

## 缺口与风险

1. **设计缺失**：没有约定新工具名称、参数和结果结构，未说明检索是文本、正则、符号还是语义检索，也没有排序、过滤、截断、错误和验收规则。现有实现是否满足设计无法判定。请提供设计文档，或明确上述契约及预期使用场景，再沿现有注册表扩展并测试。
2. **搜索范围和敏感信息**：`filesystem.py` 遍历时使用固定跳过目录，不解析目标项目的 `.gitignore`；只特别阻止 RevoCLI 自身的 `.env`，其他工作区的敏感文件仍可能被搜索并送入模型上下文。应在设计中明确忽略和敏感文件策略，再用临时工作区测试。
3. **现有检索是有限扫描**：`search_text` 是逐行字面字符串匹配，没有正则、符号理解或语义索引；扫描预算和文件大小限制可能导致不完整结果，长行文本被截断。调用方应关注 `truncated`、`limit_reason` 和 `skipped_files`；是否需要增强取决于设计。
